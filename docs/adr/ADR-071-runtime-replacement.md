# ADR-071 — CadRuntime and CadDocument replacement

Status: accepted for the Windows Alpha runtime.

## Decision

The production desktop execution chain is:

`ProjectManager → CadRuntime → CadDocument → CadDocumentRepository → CadDocumentSceneProjection → CadSceneGraph → ProfessionalCadViewportWidget`.

`CadRuntime` owns the active document, imported mesh/shape handles, display-mesh pipeline, geometry selection, operational sessions, command manager attachment, document snapshots, undo and redo. Controllers coordinate calls and expose presentation status only.

`CadDocument` is the durable source of truth for imports, references, sketches, constraints and surfaces. Its `officialExportShape` is the only shape accepted by desktop export. Document state and undo/redo snapshots are written atomically to `cad-document.json` and `cad-document-history.json` in the active project.

`CadSceneGraph` is a visual projection. Durable entities can only reach it through `CadDocumentSceneProjection`. Preview entities are transient projection state owned by `CadRuntime`; they are never promoted to document geometry until confirmation.

## Import and display

STL, STEP and IGES use the same desktop path:

`ImportExportApi → ImportedCadDocument → CadRuntime.registerImport → CadDocumentRepository → CadDocumentSceneProjection → viewport`.

STL stores its official kernel mesh and inspected triangle data. STEP and IGES store their official `ShapeHandle`; OCCT display tessellation is generated by `KernelDisplayMeshPipeline` and persisted under the active project. No imported mesh is treated as a synthetic BRep.

## Export

Desktop export resolves only `CadDocument.officialExportShape`. On project restoration, a persistent OCCT shape is restored from the project `NativeShapes` payload before export when the active kernel supports `PersistentGeometryKernelAPI`.

## Bootstrap

The process-wide `EngineeringBootstrap` registers stateless engines, APIs and factories only. It no longer creates project repositories using `Directory.current` and no longer owns a competing engineering document/runtime.

## Compatibility

Legacy STL import history is read only as a one-time migration when a project has no `CadDocument`. New imports of every supported format use the unified runtime path. Legacy feature repositories remain input adapters while their entities are projected into `CadDocument`; they are not viewport or export authorities.
